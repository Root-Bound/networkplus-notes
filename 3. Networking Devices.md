Every device has a purpose, once installed, it can often be difficult to remove. Refer to [[2. OSI-Model]] for where the devices are usually placed

Most common devices:
Router #router
	used to route traffic between IP-Subnets. OSI-Model #layer3 device.
	These IP-Subnets can be next to eachother in the same datacenter or across the world.
	This routing functionality can also be included inside an existing switch, referred to as layer 3 switches.
	So the Switch itself still operates at OSI #layer2 but the router WITHIN the switch operates at #layer3.
	Often connects diverse Network types like LAN (Local Area Network), WAN (Wide Area Network), copper (Ethernet), Fiber
Switch #switch
	Operates at #layer2. These operate mostly in hardware, forwards traffic based on data link address. The hardware within the switch is called ASIC (Application-Specific integrated circuit)
	Has many Ports and features, especially at enterprise layer. May provide #PoE to devices like Access Points, CCTV IP Cameras, Intercoms, Media Converters, and alot more. If the switch has routing capability it can also be referred to as a Multilayer switch
Firewall #firewall
	A traditional firewall lets you filter traffic based on a TCP or UDP port number (like port 554 for RTSP-Streams for example). 
	Modern firewalls are called NGFW's (next gen firewalls) which can filter traffic based on applications on the network, are able to encrypt traffic via VPN between sites. 
	Common to have a firewall at multiple remote sites so they can communicate via VPN.
	Most firewalls can be layer 3 devices, often sit at ingress or egress sites of the network.
	The firewall manages the communication between the inside and the outside of the network.
	Many firewalls also provide Network Address Translation (NAT) and dynamic routing.
IDS/IPS #intrusiondetection #intrusionprevention
	Usually already integrated in modern firewalls. They block most known vulnerabilities. Prevention system (IPS) is preferred because they can stop the threat while the IDS only alarms it.
Load Balancer #loadbalancer
	Multiple servers, invisible to the end-user. Web-server farms use these, they have very fast convergence and realize fast when a device is failing so there is no down time. Load balancers are very fault tolerant. The servers can offload a lot of work to the load balancer, like TCP Protocol overhead or handling the SSL Encryption/Decryption so the servers have more power. They also cache data so the data can be accessed faster. 
	Handles prioritization, so the end users get the fastest response time possible and also provide content switching, so only certain types of content are only on certain servers, so that no server has to single-handedly handle all requests.
Proxies #proxies
	Sits between the users and the external network. Receives the user's request and sends them on their behalf. 
	Proxies are useful for faster and safer content delivery because they can be used for caching. If the content is already cached, then the proxy can provide the content without ever having to go towards the internet. They also provide access control, URL filtering and content scanning, so that the user doesn't get any malicious software.
NAS #nas
	Network Attached Storage, Connect to a shared storage device across the network, file level access. So if you change a file, you have to write the entire file back to the NAS
SAN #san
	Storage Area Network, looks and feels like a storage device and is very similar to a NAS but it has block-level access. It is very efficient, so that when you have very large files, you can just change a little bit of information within that file, at a fraction of the time-cost. Both NAS and SAN's need alot of Bandwidth and may get their own Network
Access Points #ap
	Not a wireless router like at home, just used for wireless communication, bridges wireless to the wired network, #layer2 device. It is pervasive and depending on the size of the building you may need more Access Points so that the end-users can seamlessly roam without losing connection
Wireless LAN Controllers #WLANControllers
	Is the centralized management of access points, so that we can manage the entire enterprise from a single chair. We can deploy new access points from it, perform performance and security monitoring and be alerted if anything happens to our #ap. Often proprietary.
